# Maintenance: development, release and signing

Notes for the author. Nothing here is needed to use the script. Same organisation as
Badassium238.

Python is used only by the maintenance tools of `tools/`, on the author's machine: it is never
packaged, installed or run by the script.

## 1. Initial publication (done in 1.0.0, kept for reference)

1. The user name `jps-34` is in place everywhere (READMEs, repository page, script header) and the
   update repository is built in `docs/`. To rebuild it after changing the script:

   ```bash
   python3 tools/build_repo.py --user jps-34
   ```

2. Create the `CommonCrop` repository on GitHub (public), then push `main` and `dev`.

3. On GitHub: *Settings > Pages > Build and deployment > Deploy from a branch*, branch `main`,
   folder `/docs`. The PixInsight repository is then served at
   `https://jps-34.github.io/CommonCrop/`.

4. Test: in PixInsight, *Resources > Updates > Manage Repositories*, add this URL, then
   *Check for Updates*. Until it is signed, the *Allow unsigned update repositories* security
   option is required.

## 2. Signing (once and for all)

References: [Script code signing](https://pixinsight.com/doc/docs/ScriptCodeSigning/ScriptCodeSigning.html)
and [Update repositories](https://pixinsight.com/doc/docs/PIRepositoryReference/PIRepositoryReference.html).
Same `.xssk` keys as for Badassium238; the file stays out of Git (`.gitignore`).

## 3. dev branch, then production

`main` = production: GitHub Pages serves `docs/` from `main`, so everything that lands on `main`
reaches PixInsight users. A new version goes to `dev` first.

**Only source to edit: `scripts/CommonCrop.js`** (V8, PixInsight 1.9.4 and later). `docs/`
(archive, digest, `updates.xri`) is generated by `python3 tools/build_repo.py --user jps-34`.

Putting a new version on dev from an archive:

```bash
cd <local repository folder>/CommonCrop
git switch dev
git rm -rq .
unzip -o <download folder>/CommonCrop-vX.Y.Z.zip -d /tmp/cc
cp -a /tmp/cc/CommonCrop/. .
git add -A
git status                     # check the list before committing
git commit -m "CommonCrop X.Y.Z"
git push
```

Test in PixInsight: *Script > Execute Script File*, pick `scripts/CommonCrop.js` in the local
repository. The script runs without being installed; the production version stays in place.

Releasing once validated:

```bash
git switch main
git merge dev
git tag -a vX.Y.Z -m "CommonCrop X.Y.Z"
git push origin main --tags
git switch dev
```

Then, in PixInsight, *Resources > Updates > Check for Updates*.

With signing, order matters: sign `scripts/CommonCrop.js` with **CodeSign**, run
`python3 tools/build_repo.py --user jps-34`, sign `docs/updates.xri` last, then commit.

## 4. Versions and history

* Numbering `MAJOR.MINOR.PATCH`: patch = bug fixed with no intended change in results, minor = new
  feature, major = incompatible settings or results.
* Each published version has its `vX.Y.Z` tag. The PixInsight repository (`docs/`) only serves
  the latest one; older versions stay available through git.
* Getting a file from an older version:
  `git show v1.0.1:scripts/CommonCrop.js > CommonCrop-1.0.1.js`

## 5. Adding a camera

The `CAMERA_SIZES` table at the top of `scripts/CommonCrop.js` gives the native resolution (bin 1)
of a few cameras, recognised by the `INSTRUME` keyword. Adding a `{ match: /.../i, w, h }` line is
enough; the binning is read from `XBINNING`.
